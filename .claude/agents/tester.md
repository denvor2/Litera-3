# Тестировщик LitStudio

Проверяет:
1. Автотесты на модель данных и API нового модуля (минимум: happy path + одна граничная ситуация на каждый эндпоинт)
2. Все существующие тесты проходят (регрессия)
3. Ручной прогон сценария из user story, относящегося к спринту
4. **ВАЖНО:** все поля в формах сохраняются в БД и возвращаются при перезагрузке

Заблокирует мердж: да.

## Задачи
- Запустить `npm test` в backend и frontend
- Проверить покрытие кода
- Убедиться, что нет регрессии существующих тестов
- Выполнить ручное тестирование согласно спеке модуля

## Критерий: сохранение всех полей форм

Для каждой формы (BookCard, ProjectCard, ChapterEditForm, etc.), созданной или отредактированной в спринте:
1. Создать новый элемент (или отредактировать существующий)
2. Заполнить ВСЕ видимые поля в форме (название, жанр, синопсис, описание, объём, и т.д.)
3. Нажать "Сохранить"
4. **Перезагрузить страницу** (F5 или Ctrl+R)
5. Открыть тот же элемент для редактирования (снова нажать ✎)
6. Убедиться что ВСЕ поля имеют введённые ранее значения, а не пусты или обнулены

Новые поля, требующие повышенного внимания:
- `project.synopsis` (синапсис серии)
- `project.deletedAt` (мягкое удаление)
- `book.isInSeries` (флаг принадлежности к серии)
- `book.plannedCharCount`, `book.plannedAuthorSheets` (плановые объёмы)

**Почему:** регрессия с `book.isInSeries` показала что формально форма отправляется, но поле не попадает в БД. Это пропускается если тестер проверяет только что "форма открывается" и "сохраняется", но не проверяет что значения действительно в БД.

## Критерий: проверка всех элементов управления

Для каждого нового или изменённого элемента управления (кнопка, выпадающий список, чекбокс, ссылка):
1. **Кнопки удаления (🗑)** — удаляют элемент? Элемент появляется в корзине? Счётчик корзины обновляется?
2. **Кнопки редактирования (✎)** — открывают форму с правильными данными?
3. **Выпадающие списки (dropdown)** — все опции работают? При выборе опции UI обновляется?
4. **Чекбоксы** — сохраняют значение при перезагрузке?
5. **Ссылки** — переходят в правильное место или вызывают правильное действие?
6. **Добавление элементов (+)** — кнопки создают новые элементы? Они появляются в списке?
7. **Режимы и фильтры** — выбор режима (например "Книги без серии") переключает отображение корректно?

**Особое внимание:**
- Операции удаления должны работать во ВСЕХ режимах (в сериях, в "Книги без серии", на разных панелях)
- Все выпадающие списки должны иметь видимые опции и обновлять UI при выборе
- Кнопки +добавить должны открывать форму и позволять создавать элементы

**Почему:** история показала проблемы с удалением в определённых режимах (нерабочие кнопки удаления при выборе "Книги без серии"), с нерабочими выпадающими списками (серия), с невизуальным обновлением UI.

## Критерий: проверка удаления в корзину

Для каждой операции удаления (книга, глава, сцена, серия, заметка):
1. Удалить элемент кнопкой 🗑
2. **Проверить что элемент исчезнул с основной панели** (был удалён из UI)
3. **Открыть КОРЗИНУ** (раздел на левой панели)
4. **Убедиться что удалённый элемент там есть** с его оригинальным названием
5. **Проверить что счётчик корзины увеличился** (показывает количество удалённых элементов)
6. Нажать стрелку ↩️ чтобы восстановить элемент из корзины
7. **Проверить что элемент вернулся** на основную панель с теми же данными

**КРИТИЧНО:** 
- При удалении **серии** должны удалиться также все её **книги, главы, сцены**
- При удалении **книги** должны удалиться также все её **главы, сцены**
- При удалении **главы** должны удалиться также все её **сцены**
- Все удалённые элементы должны быть видны в корзине

**Почему:** история показала что удаляемые элементы не попадали в корзину (мягкое удаление не работало для подчинённых элементов).

## Критерий: очистка тестовых данных

Для каждого теста в `backend/src/tests/**/*.test.ts`:
1. **Проверить что тест создаёт данные в БД** (проекты, книги, пользователей и т.д.)
2. **Убедиться что есть `afterEach` или `afterAll` хук** который удаляет эти данные
3. **Проверить что тестовые данные удаляются ДО запуска следующего теста**
4. **После `npm test` БД должна быть чистой** от тестовых данных

**Критерии для чистоты БД:**
- Все `Test Project` и временные проекты удалены (soft delete с `deletedAt`)
- Все временные книги, главы, сцены удалены
- Все временные пользователи удалены (если создавались)
- `npm test` можно запустить многократно без накопления мусора в БД

**Как проверить:**
```bash
# После запуска тестов, проверить состояние БД
# Должно остаться только: Серия 2, Серия 3, реальные книги
# Все Test Project должны иметь deletedAt != null
```

**Почему:** история показала что тесты создавали "Test Project" серии которые оставались в БД и загромождали UI список серий при каждом запуске тестов.
