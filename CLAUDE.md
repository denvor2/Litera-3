# LitStudio 2 — инструкции для Claude Code

## Язык
Проект на русском. Все ответы, комментарии в коде, сообщения коммитов, тексты уведомлений — на русском. Идентификаторы в коде (переменные, функции, таблицы БД) — на английском, это стандарт для кода независимо от языка проекта.

## Режим работы: без вопросов внутри спринта
Один раз в начале спринта Клод Код получает: файл спеки модуля (`docs/specs/NN-*.md`), `docs/data-model.md`, `docs/DOD.md`. Этого достаточно для самостоятельной работы.

- Внутри спринта не задавать пользователю уточняющих вопросов и не запрашивать подтверждений на промежуточные решения.
- Если в спеке реально не хватает информации — принять самостоятельное решение, зафиксировать его комментарием в коде и строкой в файле `docs/DECISIONS.md` (создать, если его ещё нет: дата, спринт, что решено, почему).
- Единственное сообщение пользователю за спринт — уведомление по завершении (см. шаблон ниже). Никаких сообщений в процессе.

### Шаблон уведомления между спринтами
```
Спринт N — [название модуля] — завершён / заблокирован

Сделано:
- ...

Отклонения от спеки (если есть, со ссылкой на docs/DECISIONS.md):
- ...

Заблокировано (если есть):
- что именно и почему

Следующий спринт: [модуль/пункт]
```

## Стек (зафиксирован для Фазы 0)
Обоснование выбора — в `docs/specs/00-overview.md`.
- Фронтенд: React + TypeScript + Vite
- Редактор текста: TipTap
- Backend: Node.js + Fastify + Prisma
- БД: PostgreSQL
- Тесты: Vitest (backend и frontend-логика), Playwright — только если/когда потребуется e2e (не в Фазе 0 по умолчанию, добавить если UI-ревью найдёт регрессии, которые модульные тесты не ловят)

Менять стек можно только явным решением владельца проекта, не по инициативе Клод Кода в процессе спринта.

## Точность реализации дизайна — обязательна, не "по мотивам"
`design/mockup/index.html` — не референс для вдохновения, а буквальная спецификация структуры, отступов, цветов и поведения. Наблюдалась проблема: реализация расходится с мокапом не в мелочах, а в самой структуре компонента (например, вместо переключателя текущей книги — сплошной список всех книг серии; вместо текстовой ссылки — кнопка с рамкой в акцентном цвете).

Обязательно перед тем как считать UI-часть спринта готовой:
1. **Открыть `design/mockup/index.html` именно как файл** (через инструмент чтения файла), не полагаться на пересказ в `UI-SPEC.md` как на самостоятельно достаточный источник — `UI-SPEC.md` объясняет *логику* поведения, но конкретные CSS-переменные, классы и разметку нужно брать из самого HTML.
2. Переносить **структуру разметки** (какой элемент во что вложен, что явно текст-ссылка, а что кнопка с рамкой, что показывается только по hover) — не изобретать эквивалентную по смыслу, но другую по форме структуру.
3. Переносить **цветовые токены** как есть (`--accent`, `--selected-bg` и т.д. из `:root` в мокапе) — если использован акцентный цвет (`--accent`, тёмно-бордовый), проверить по мокапу, для чего именно он зарезервирован (в дизайне — только подсветка упоминаний Кодекса и primary-кнопки в формах, не рамки обычных кнопок вроде «+ добавить главу», которые в мокапе — простая текстовая ссылка без рамки и без акцентного цвета).
4. После реализации — сравнить со скриншотом/рендером `design/mockup/index.html` бок о бок, не полагаться на память о том, "что примерно похоже". Несовпадение — не мелкая деталь, а повод переделать, а не подправить.
5. `docs/UI-VERIFICATION-CHECKLIST.md` (см. финальный прогон Фазы 0 в `docs/DOD.md`) — построчный список поведения именно для такой сверки, использовать его не только в конце Фазы 0, а как ориентир уже по ходу реализации левой панели, AI-панели и т.д.

## Git
- Ветка на спринт: `sprint/NN-module-name`
- Коммиты — по-русски, в формате `<модуль>: <что сделано>` (например: `рукопись: автосохранение сцены с дебаунсом`)
- Мердж в `main` — только после прохождения всех пунктов `docs/DOD.md`
- Не коммитить в `main` напрямую (уже настроено в существующем git-publisher субагенте — использовать его)

## Порядок работы над спринтом
1. Прочитать файл спеки модуля + `docs/data-model.md` + `docs/DOD.md`
2. Реализовать
3. Прогнать `.claude/agents/tester.md` (тесты)
4. Прогнать `.claude/agents/code-quality.md`
5. Прогнать `.claude/agents/architect.md`
6. Если менялся UI — прогнать `.claude/agents/ui-reviewer.md` и `.claude/agents/designer.md`
7. Мердж, уведомление, следующий спринт

```
/frontend

/.claude/agents — субагенты-ревьюеры
```
