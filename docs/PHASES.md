# Фазы проекта LitStudio 2

Одно правило на все фазы: **следующая фаза не начинается, пока не закрыт DoD (см. DOD.md) предыдущей**. Ничего не строим "заранее на вырост" внутри кода — только там, где явно помечено "точка расширения".

---

## Фаза 0 — MVP (веб, один пользователь)

Цель: рабочий редактор рукописи с минимальным Кодексом, который можно реально использовать для письма одной книги. Без сети, без AI, без совместной работы.

**Входит:**
- Модуль «Рукопись»: Книга → Глава → Сцена (без «Бита» — добавим в Фазе 2, если понадобится темп-трекинг)
- Карточка сцены: заголовок, статус, POV, локация (ссылка на Кодекс), счётчик слов
- Drag-and-drop сцен/глав
- Полноэкранный режим письма
- Автосохранение (просто дебаунс-сохранение в БД, без CRDT и без офлайна)
- Базовый Кодекс: Персонажи и Локации, без вложенности, без кастомных типов
- Инлайн-подсветка упоминаний имён из Кодекса в тексте (точное совпадение имени, без склонений — Фаза 2 добавит морфологию)
- Счётчики: слова, знаки с/без пробелов, а.л., страницы
- Экспорт в .docx
- Одна БД, один пользователь, без логина (решено: логин не нужен на этом этапе)

**Явно НЕ входит:** доска сюжета, таймлайн, AI-эксперты, конспект, импорт, любой офлайн, любая синхронизация, десктоп/мобильный клиенты, совместная работа.

**Технически:** одна БД PostgreSQL, один backend-процесс, один фронтенд (веб). Никакого API Gateway/Sync-сервиса/Auth-сервиса как отдельных сервисов — это Фаза 3.

---

## Фаза 1 — Деплой и укрепление MVP

Цель: то же самое, но на реальном сервере, с приемлемой надёжностью, чтобы можно было писать в проде каждый день.

- Продакшн-деплой (хостинг backend + БД + статика фронта)
- Резервное копирование БД (ежедневный бэкап — must have до того, как туда попадёт реальная рукопись)
- Базовое версионирование сцены (история правок с откатом) — это как раз то, что раньше подстраховывал бы CRDT, но без сети и совместной работы это просто снапшоты в БД по таймеру/по значимым изменениям
- Полнотекстовый поиск по проекту
- Тёмная/светлая тема, настройка ширины колонки — низкий риск, высокая ценность для UX

---

## Фаза 2 — Инструменты писателя

Цель: то, что превращает текстовый редактор в инструмент для художки — доска сюжета, конспект, таймлайн, AI.

- Доска сюжета (Plot Board) + сюжетные линии
- Конспект (Outline)
- Таймлайн событий
- Расширение Кодекса: вложенность локаций, кастомные типы сущностей, граф отношений персонажей
- Цели и статистика (дневная/недельная цель, стрики, графики)
- AI-эксперты (Соавтор/Редактор/Критик/Читатель + кастомные) — как отдельный, полностью отключаемый AI-сервис (прокси к внешнему LLM API), изолированный от остального
- Импорт (.docx/.md с разбиением по заголовкам)
- Экспорт в .epub/.fb2/.pdf

---

## Фаза 3 — Мультиплатформенность и синхронизация

Цель: то, ради чего в изначальном ТЗ появились CRDT/Tauri/React Native — самая рискованная и дорогая часть, поэтому она в конце, когда продукт уже используется и оправдывает инвестицию.

- Десктоп-клиент (Tauri) с локальной SQLite и офлайн-режимом
- Мобильный клиент (React Native)
- CRDT-синхронизация текста сцены (Yjs) между устройствами
- Sync-сервис (WebSocket) + conflict resolution
- Совместная работа (роли: владелец/редактор/комментатор/читатель), инлайн-комментарии

**Не начинать эту фазу, пока Фаза 0–2 не используются на реальных рукописях минимум несколько недель** — иначе ты будешь синхронизировать модель данных, которая ещё поменяется.
