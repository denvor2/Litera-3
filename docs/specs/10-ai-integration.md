# Модуль «AI-помощники» — Фаза 1 (интеграция)

**Источник:** п. 3.8, 3.11 исходного ТЗ; `design/mockup/UI-SPEC.md`, раздел «Правая зона — AI-помощники»; `08-ai-experts.md` (черновик Фазы 2, переносим интеграцию в Фазу 1).

Цель: подключить реальную работу с LLM внутри структуры, уже созданной в Фазе 0. Панель справа перестаёт быть визуальной заглушкой — ассистенты начинают отвечать. В Фазе 1 функция новая, в Фазе 2 расширяется (новые типы запросов, новые ассистенты, интеграции).

---

## Как решено из Фазы 0 / предусловия

- **Контекст разделён** (из `08-ai-experts.md`):
  - **Кодекс** (персонажи, локации) — все на уровне **серии** (`PROJECT`)
  - **Текст рукописи** — только текущая **книга** (`BOOK`), без других книг серии
  - Практически: при сборке промпта разные запросы к БД по `project_id` и `book_id`

- **Всю книгу в промпт, не RAG** — полный текст текущей книги (все главы/сцены) + полный Кодекс серии как контекст-основа. Обрезка по лимиту контекста (если текст > лимита LLM) — отдельный спринт Фазы 2, тут не делаем.

- **Раскладка и паттерны UI** — уже есть в Фазе 0 мокапе, касается:
  - Четыре роли (Соавтор / Редактор / Критик / Читатель) как чипы, кликабельные
  - У каждой роли — три типовых запроса (быстрые кнопки под чипами)
  - Масштаб запроса (Сцена / Глава / Диалог / Выделение) — отдельный от контекста
  - Выделение текста мышью → автоматический переход масштаба на «Выделение»
  - Диалог в панели (форма внизу, история над ней)
  - Шестерёнка ⚙ на каждой роли для редактирования промпта и настроек

## Acceptance-критерии

### 1. LLM-интеграция (бэкенд)

#### 1.1 Выбор провайдера
- **Поддерживаемые провайдеры** (в порядке приоритета):
  1. **Claude API** (Anthropic) — основной, оптимизируем под него
  2. OpenAI (GPT-4, GPT-3.5-turbo)
  3. Yandex GPT
  4. Ollama (локальный, для dev-среды)
  5. Другие (расширяемая архитектура)

- **Конфигурация** (`.env`):
  ```
  AI_PROVIDER=claude|openai|yandex|ollama
  AI_MODEL=claude-3-5-sonnet|gpt-4|yandex-gpt-latest|ollama-model-name
  CLAUDE_API_KEY=...
  OPENAI_API_KEY=...
  YANDEX_API_KEY=...
  OLLAMA_ENDPOINT=http://localhost:11434
  ```

- В коде: Fastify-эндпоинт `POST /api/ai-query` принимает **абстрактный запрос** (контекст, промпт-инструкция, масштаб, текст) и делегирует провайдеру через фабрику.
- **Интерфейс провайдера**:
  ```ts
  interface LLMProvider {
    query(options: {
      systemPrompt: string;
      context: string;
      userMessage: string;
      temperature?: number;
      maxTokens?: number;
    }): Promise<{
      text: string;
      tokensUsed: number;
      tokensLimit?: number; // для предупреждений о лимите
    }>;
  }
  ```
  Реализация для каждого провайдера — отдельный модуль в `backend/src/ai-providers/`.

#### 1.2 Сборка контекста для запроса

**Контекст зависит от структуры библиотеки:**

- **Если книга в Серии** (`BOOK.project_id` не NULL):
  - Все книги в этой Серии (полный текст каждой: сцены/главы)
  - Полный Кодекс Серии (персонажи, локации по `CODEXENTRY.project_id`)
  - Все Заметки (Идеи) всех книг в Серии (по `IDEA.project_id`)
  - Логика: ассистент видит полный мир, понимает связи между книгами

- **Если книга без Серии** (`BOOK.project_id` IS NULL, `BOOK.title` = название, это самостоятельная книга):
  - Только текст этой книги (сцены/главы)
  - Кодекс только этой книги (элементы по `CODEXENTRY.book_id`)
  - Заметки только этой книги (по `IDEA.book_id`)

- **Форматирование контекста**: чистый текст, структурирован заголовками:
  ```
  === КОДЕКС ===
  
  Персонажи:
  - Ксения (перс.): Внешность — высокая, рыжая...
  - Механик Вадим (перс.): ...
  
  Локации:
  - Портовый док №4 (лок.): ...
  
  === ИДЕИ ===
  
  - ...
  
  === РУКОПИСЬ ===
  
  Книга 1: Слон, которого не было
  
  Глава 1: Прибытие
  [полный текст сцен]
  
  ...
  ```

- **Сборка «предмета запроса»** (зависит от масштаба, см. 1.3–1.6 ниже) — это **отдельно** от контекста, передаётся в промпт как "вот на это сфокусируйтесь, остальное — справка".

#### 1.3 Масштабы запроса и сборка текста по масштабу

**Масштаб** — это на какой конкретный фрагмент сфокусирован запрос. Контекст (что ассистент знает) остаётся всегда полным (Фаза + Кодекс), но в промпт передаётся **один из масштабов**.

**A) Редактор — масштабы текста рукописи:**

- **Сцена** (по умолчанию):
  - Текст текущей развёрнутой сцены (из `SCENE.content`)
  - API: `GET /api/scene/:sceneId` → текст + метаданные

- **Глава**:
  - Все сцены текущей главы, объединены в один текст
  - Заголовки сцен видны (структура сохранена)
  - API: `GET /api/chapter/:chapterId/full-text`

- **Диалог**:
  - Распознавание диалоговых блоков (начинаются с `— ` или `«...»`)
  - Фокус на одном диалоговом фрагменте
  - API: `GET /api/scene/:sceneId/dialogues` → список; затем по ID конкретного

- **Выделение**:
  - Произвольный фрагмент, выделенный мышью в редакторе
  - Фронтенд отправляет текст выделения в запросе
  - Пример типовых запросов: "Переформулируй это выразительнее", "Найди ошибку в этом абзаце"

**B) Заметки (Идеи) — масштаб «Идея»:**
- Весь текст одной Заметки (одного элемента `IDEA`)
- Типовые запросы: "Разверни эту идею подробнее", "Как это вписывается в сюжет?"
- Доступен при открытии Заметки в центре

**C) Элементы Кодекса — масштаб «Элемент»:**
- Выбранный персонаж/локация/другой элемент (все его поля из карточки в центре)
- Типовые запросы (примеры): 
  - "Предложи конфликт для этого персонажа"
  - "Какие второстепенные персонажи могут взаимодействовать с этой локацией?"
- Доступен при открытии карточки Кодекса в центре

**D) Поля форм — масштаб «Поле»:**
- Любое редактируемое поле формы (Заголовок, Аннотация, Синопсис, Описание персонажа и т.д.)
- Механика: под каждым полем `.bc-textarea` показываются типовые запросы для этого поля (см. раздел 2.X ниже)
- Пример: в форме Книги, в поле Аннотация:
  - Типовой запрос 1: "Напиши аннотацию, которая привлечёт читателя"
  - Типовой запрос 2: "Переформулируй эту аннотацию, чтобы было короче"
  - Типовой запрос 3: "Проверь аннотацию на типичные ошибки"
- Клик по такому запросу открывает AI-панель справа, переключает масштаб на "Поле" и отправляет запрос
- Контекст при этом остаётся полный (всё, что ассистент знает о Книге/Проекте), но фокус — на аннотации

**Структура масштабов в API:**
```json
{
  "scope": "scene|chapter|dialogue|selection|idea|codex-element|field",
  "scopeId": "uuid (if applicable)",
  "scopeLabel": "Заголовок сцены / Аннотация книги / и т.д. (for UI)",
  "scopeText": "содержимое, на что фокусируемся"
}
```

#### 1.4 API-эндпоинты

##### POST /api/ai-query
Единый эндпоинт для всех запросов к ассистентам.

```json
{
  "bookId": "uuid",
  "role": "coauthor|editor|critic|reader|custom",
  "scope": "scene|chapter|dialogue|selection|idea|codex-element|field",
  "scopeId": "uuid (context-dependent)",
  "scopeLabel": "string (for UI display, e.g. 'Аннотация книги')",
  "scopeText": "string (required, content to focus on)",
  "userMessage": "string (user's query or quick prompt text)",
  "customPrompt": "string (optional, if role=custom)"
}
```

Ответ:
```json
{
  "success": true,
  "assistantMessage": "string (LLM response)",
  "tokensUsed": 123,
  "tokenLimit": 8000,
  "tokensRemaining": 7877,
  "warnings": [
    "Контекст обрезан: используются последние 25 сцен из 40"
  ],
  "timestamp": "ISO"
}
```

**Важные поля ответа:**
- `tokensUsed` — токены, использованные в этом запросе
- `tokenLimit` — лимит контекста провайдера
- `tokensRemaining` — приблизительно сколько осталось до лимита
- `warnings` — массив предупреждений (обрезка контекста, близость к лимиту)

Сохранять лог диалога в памяти (в Фазе 1 пока в памяти приложения, в Фазе 2 — в БД).

##### GET /api/book/:bookId/full-text
Полный текст книги + Кодекс серии (для отладки/для предварительного просмотра контекста в интерфейсе).

##### Вспомогательные (уже могут быть, или добавить):
- GET /api/scene/:sceneId (текст сцены)
- GET /api/chapter/:chapterId (текст главы)
- GET /api/chapter/:chapterId/full-text (все сцены главы)
- GET /api/scene/:sceneId/dialogues (список диалогов)

#### 1.5 Сохранение ролей и их настроек

Каждая роль (Соавтор / Редактор / Критик / Читатель, + пользовательские) — это запись в новой таблице `AI_ROLE`:

```sql
CREATE TABLE AI_ROLE (
  id UUID PRIMARY KEY,
  project_id UUID NOT NULL REFERENCES PROJECT(id),
  name VARCHAR(255) NOT NULL,
  type VARCHAR(50), -- 'coauthor' | 'editor' | 'critic' | 'reader' | 'custom'
  system_prompt TEXT, -- инструкция, что делает эта роль
  quick_prompts TEXT[] -- 3 типовых запроса (JSON или массив строк)
  model VARCHAR(100), -- в Фазе 0 не используется (общая модель), в Фазе 2 — per-role override
  is_deleted BOOLEAN DEFAULT FALSE,
  created_at TIMESTAMP,
  updated_at TIMESTAMP
);
```

- Четыре предустановленные роли создаются при создании проекта (`PROJECT`)
- Пользователь может редактировать их промпт и типовые запросы (кнопка ⚙ на каждой роли)
- **Пользовательская роль** — клик на «+ свой», открывается форма с пустыми полями (Название, Промпт, Типовые запросы)

#### 1.6 Безопасность / ограничения

- **Лимит на размер контекста**: если полный текст книги + Кодекс > лимита LLM-провайдера, обрезаем **текст рукописи** до N последних сцен (Кодекс остаётся полным). Конкретное значение N — параметр, решается при выборе провайдера.
- **Rate limiting**: не более 10 запросов в минуту на пользователя (базовое ограничение, уточняется в зависимости от квот провайдера)
- **Ключи API**: никогда не отправлять в фронтенд. Бэкенд хранит в переменных окружения (`.env`), фронтенд всегда идёт через `/api/ai-query`.

### 2. Фронтенд — правая панель (UI)

Раскладка и компоненты уже есть в мокапе (`design/mockup/index.html`, `.ws-right`). Нужно сделать их работающими.

#### 2.1 Чипы ролей
- Четыре чипа (Соавтор, Редактор, Критик, Читатель) + чип «+ свой» для пользовательских ролей
- Клик по чипу = переключить **активную роль** (голубая заливка `--selected-bg`)
- Клик по **шестерёнке ⚙** на чипе = открыть форму настроек этой роли в центре (вид 7, как в мокапе)
- Типовые запросы меняются при переключении роли

#### 2.2 Типовые запросы (быстрые кнопки)
- Три кнопки под чипами, специфичные для активной роли
- Конкретные тексты запросов для каждой роли:
  - **Соавтор**: 
    1. "Продолжи сцену на 3–4 абзаца в этом же тоне"
    2. "Переформулируй эту часть, чтобы было выразительнее"
    3. "Что не хватает в этой сцене?"
  - **Редактор**:
    1. "Найди логические разрывы в этой сцене"
    2. "Персонажи говорят натурально? Найди неловкие диалоги"
    3. "Что можно сократить без ущерба?"
  - **Критик**:
    1. "Что не работает в этой сцене?"
    2. "Какие стереотипы здесь проявляются?"
    3. "Насколько эта сцена необходима для сюжета?"
  - **Читатель**:
    1. "Что я почувствую, читая это впервые?"
    2. "Где я запутался в сюжете?"
    3. "Насколько убедительна мотивация персонажа?"

- Клик по кнопке = отправить её текст как `userMessage` в `/api/ai-query`
- **Список типовых запросов редактируется** в форме настроек роли (вид 7, при клике на ⚙)

#### 2.3 Масштаб запроса (.ai-scope-row)
- Четыре переключаемых кнопки: **Сцена** / **Глава** / **Диалог** / **Выделение**
- По умолчанию: **Сцена** (текущая развёрнутая)
- **Автоматическое переключение на «Выделение»**:
  - Пользователь выделяет текст в теле редактора мышью
  - Фронтенд ловит событие `mouseup` в `.body-text`, считывает выделение (`window.getSelection()`)
  - Если что-то выделено → переключает `.ai-scope-row` на кнопку «Выделение», показывает усечённую цитату выделенного текста (макс. 50 символов + «…»)
  - Клик по цитате возвращает полный текст выделения (может быть подсказкой или просто иконкой для копирования)

#### 2.4 Область диалога
- Флекс-контейнер, занимает всё оставшееся место в панели (`flex: 1`)
- История сообщений:
  - Каждое сообщение — два пузыря: один от пользователя (светло-серый), один от ассистента (белый)
  - Шапка каждого пузыря: роль ассистента / "Вы" + временная метка (опционально)
  - Скроллится вниз автоматически при появлении нового сообщения
- Пусто, если ещё нет диалога (просто `background: var(--surface-2)`, без специального пустого состояния)

#### 2.5 Форма запроса (прижата внизу)
- Однострочное текстовое поле (`.ai-input`) с плейсхолдером "Спросить помощника…"
- Кнопка отправки (⏎ или отдельная кнопка 📤 справа в поле) — отправляет запрос
- `POST /api/ai-query` с текущей активной ролью, масштабом, текущей сценой/главой и текстом запроса

#### 2.6 Загрузка и ошибки
- Во время ожидания ответа ассистента:
  - Поле ввода — disabled (серый фон, курсор запрещён)
  - Последнее сообщение от ассистента показывает спиннер или многоточие "Размышляю…"
  - Можно отменить запрос (кнопка ✕, если время ответа > 5 сек)

- Ошибка (нет ключей API, лимит квоты, таймаут):
  - Красное сообщение в диалоге: "Ошибка подключения к ассистенту: [причина]"
  - Форма ввода остаётся активной — пользователь может попробовать снова
  - Не прерывается весь интерфейс, только эта панель

#### 2.7 Настройка ширины панели (resize handle)
- Левый край панели (`.resize-handle`, 6px) — перетаскиваемый
- Диапазон ширины: **200–460px** (как в мокапе)
- При перетаскивании: обновляется CSS-переменная `--right-w` в `.ws-grid`
- **Сохранение ширины** между сессиями и устройствами:
  - Сохранять в **куках** (HttpOnly) с сроком 30 дней, или в **БД** (новое поле `USER_PREFERENCES.ai_panel_width`)
  - При загрузке страницы: если есть сохранённое значение → применить, иначе дефолт 280px
  - **Преимущество БД**: синхронизация между компьютерами для авторизованного пользователя (в Фазе 1 без авторизации — использовать куки)

### 3. Форма настроек роли (в центре, вид 7)

Открывается по клику на ⚙ рядом с ролью.

#### 3.1 Поля формы
- **Иконка роли** — выбор из набора эмодзи/иконок (🤖, ✏️, 🧐, 👁️, ⭐, 🎨, 🎯, 💡 и т.д., примерно 12–16 вариантов). Отображается перед названием в чипах роли.
  - Сохраняется в `AI_ROLE.icon` как строка
  - Для встроенных ролей: предустановленные иконки (Соавтор — 🤖, Редактор — ✏️, Критик — 🧐, Читатель — 👁️)

- **Название** — текстовое поле, например "Соавтор" (для встроенных ролей — нередактируемое, disabled)

- **Промпт-инструкция** — большое текстовое поле (`.bc-textarea`), описание того, как ведёт себя эта роль. Пример для Соавтора:
  ```
  Ты опытный писатель-соавтор. Помогаешь писателю развивать сцены,
  дополняя текст в том же стиле и тоне. Когда просят продолжить сцену —
  пишешь 2–4 абзаца, следуя установленной в Кодексе логике персонажей
  и локаций. Будь кратким, не перефразируй уже написанное.
  ```

- **Типовые запросы** — три текстовых поля, по одному на каждый быстрый запрос (редактируемые строки, по одному на поле)
  - Это быстрые кнопки, которые появляются под чипом роли в основной панели
  - В Фазе 1 могут быть общие для масштаба редактора (Сцена/Глава/Диалог)
  - В Фазе 2 будут типовые запросы, специфичные для каждого масштаба/поля (см. раздел 2.X)

- **Модель** (опционально, в Фазе 1 — может быть заглушка):
  - Переключатель "Общая (по умолчанию проекта)" / "Своя"
  - Если "Своя" — выпадающий список моделей (в Фазе 1 пока пусто, добавится при интеграции multi-model)
  - Реально заполнится в Фазе 2, но структура готова

#### 3.2 Кнопки
- **Сохранить** — обновляет запись `AI_ROLE` в БД, закрывает форму (возвращает в редактор)
- **Отмена** — не сохраняет, закрывает форму

#### 3.3 Для встроенных ролей
- Название не редактируется (disabled)
- Промпт изначально показывает встроенное значение, но может быть переписан
- Любые изменения сохраняются в `AI_ROLE` (даже встроенных ролей)

#### 3.4 Создание пользовательской роли
- Клик на чип «+ свой» открывает форму с пустыми полями (как выше)
- Заголовок формы: "Новый помощник"
- После сохранения: создаётся новая запись в `AI_ROLE` с `type = 'custom'`
- Новый чип добавляется в панель и становится активным

### 5. Типовые запросы под полями форм

Эта функция расширяет возможности масштаба "Поле": типовые запросы показываются прямо под редактируемым полем.

#### 5.1 Механика отображения
- Когда открыта любая форма (Книга, Сцена, Персонаж и т.д.) и пользователь фокусируется на поле (`.bc-textarea` или `.bc-input`):
  - Под полем появляется блок AI-помощника (если есть типовые запросы для этого поля в `AI_FIELD_PROMPTS`):
    
    ```
    Поле: [___текст_______________]
    
    ⚡ Типовые запросы:
    [Кнопка 1] [Кнопка 2] [Кнопка 3]
    
    Или напиши свой запрос:
    [___кастомный запрос___________] [📤]
    ```
  
  - **Типовые кнопки** (`.quick-ai-button`): маленькие, текстовые, стиль как в AI-панели
    - Пример для поля "Аннотация книги":
      1. "Напиши аннотацию, которая привлечёт читателя"
      2. "Переформулируй короче (1–2 предложения)"
      3. "Проверь на типичные ошибки"
  
  - **Поле кастомного запроса** (`.ai-custom-input`): однострочное или многострочное (зависит от контекста)
    - Плейсхолдер: "Или напиши свой запрос…"
    - Фокус на кнопку → можно редактировать предложенный текст
    - Отправка: ⏎ (Enter) или кнопка 📤

#### 5.2 Клик по типовой кнопке
- Клик → открывает AI-панель справа (если закрыта)
- Переключает масштаб на "Поле" (новый вид в `.ai-scope-row`, например, как выглядит: "📝 Аннотация")
- Заполняет поле ввода формы запроса текстом кнопки
- Отправляет `POST /api/ai-query` с:
  ```json
  {
    "scope": "field",
    "scopeId": "book:12345",  // или другой уникальный ID формы/поля
    "scopeLabel": "Аннотация книги",
    "scopeText": "[текущее содержимое поля]",
    "userMessage": "[текст нажатой кнопки]"
  }
  ```

#### 5.2b Кастомный запрос к полю
- Под типовыми кнопками — текстовое поле (`.ai-custom-input`, стиль как в основной AI-панели)
- Плейсхолдер: "Или напиши свой запрос…"
- Пользователь может:
  - Модифицировать предложенный текст кнопки (клик на кнопку → заполнится в поле, потом отредактировать)
  - Написать полностью свой запрос, не используя типовые
- Отправка: ⏎ (Enter) или кнопка 📤 справа от поля
- API-запрос аналогичен типовому, только `userMessage` — от пользователя

#### 5.3 Ответ и его вставка (три варианта)

Ассистент возвращает текст (обычно — вариант/редакцию поля). **Не автоматически вставлять**, показать в AI-панели с опциями вставки.

**Три способа вставки:**

1. **Заменить всё поле** (если фокус был на целом поле):
   - Кнопка "Применить" в диалоге → текст из поля полностью заменяется на ответ
   - Исходный текст теряется, но можно отменить через Undo (см. раздел 8)

2. **Заменить выделение** (если в поле был выделен текст):
   - Кнопка "Вставить в выделение" → только выделённая часть заменяется
   - Остальное содержимое поля сохраняется
   - Пример: выделили "Портовый док" → ассистент предложил "Морской причал" → клик → текст в поле стал "Морской причал"

3. **Вставить в место курсора** (если курсор просто стоит в поле, без выделения):
   - Кнопка "Вставить" → текст от ассистента вставляется в месте курсора
   - Остальное содержимое остаётся нетронутым
   - Пример: в анотации курсор стоит в конце → ассистент дополнил → текст добавился в конец

**Общее:**
- Все три операции записываются в историю Undo (см. раздел 8)
- После вставки пользователь может отредактировать результат
- Если результат не подходит → Undo или написать новый запрос ассистенту

### 7. Обработка ошибок и предупреждений

**Основной принцип**: все ошибки и предупреждения показываются в нижней строке статуса (`.ws-bottom`) с цветовой кодировкой. Дополнительно — в AI-панели (диалоге).

#### 7.1 Отображение в нижней строке статуса
Добавить новый блок в `.ws-bottom` рядом с индикатором сохранения:

- **Критические ошибки** (розовый/красный фон `#F3E3E1` / `#A32D2D` на тексте):
  - Фон: розовый полупрозрачный
  - Иконка: 🔴
  - Текст: ошибка (максимум 60 символов, остальное обрезать)
  - Пример: `🔴 Ошибка: проверьте API-ключ`
  - Кликабельна: клик → открыть Настройки или AI-панель с деталями

- **Предупреждения** (жёлтый фон `#F3E3E1` / `#B9812E` на тексте):
  - Фон: жёлтый полупрозрачный
  - Иконка: ⚠️
  - Текст: предупреждение (максимум 60 символов)
  - Пример: `⚠️ Контекст на 85% лимита`
  - Информационна: клик → показать детали (всплывающая подсказка или перейти в AI-панель)

- **Автоскрытие**:
  - Критические ошибки: не скрываются, пока пользователь не исправит или не кликнет на них
  - Предупреждения: автоматически исчезают через 8 сек, или при клике
  - При новой ошибке/предупреждении старое заменяется (не стекируется)

#### 7.2 Нет ключа API / неправильный ключ
- Ответ `401 Unauthorized` от эндпоинта `/api/ai-query`
- **Нижняя строка**: `🔴 Ошибка: проверьте API-ключ` (розовый фон)
- **AI-панель**: красное сообщение в диалоге: "🔴 Ошибка аутентификации. Проверьте API-ключ в Настройках."
- Клик на нижнюю строку → открывает Настройки

#### 7.3 Превышение лимита квоты или rate-limiting
- Ответ `429 Too Many Requests`
- **Нижняя строка**: `⚠️ Лимит запросов исчерпан` (жёлтый фон, исчезает через 8 сек)
- **AI-панель**: сообщение в диалоге: "⚠️ Лимит запросов исчерпан. Попробуйте позже."
- Форма остаётся активной для повторной попытки

#### 7.4 Таймаут (> 30 сек)
- **AI-панель**: "⏳ Ассистент долго думает…" со спиннером
- Кнопка отмены (✕) отправляет `DELETE /api/ai-query/:requestId`
- После отмены диалог восстанавливается до состояния перед запросом
- **Нижняя строка**: не показывать (это не критично)

#### 7.5 Лимит размера контекста превышен
- **Нижняя строка**: `⚠️ Контекст на 85% лимита` (жёлтый фон, исчезает через 8 сек)
- **AI-панель**: 
  - Предупреждение в диалоге:
    ```
    ⚠️ Контекст слишком большой, используются последние 25 из 45 сцен.
    Рекомендуем архивировать завершённые части или разделить на несколько книг.
    ```
  - **Индикатор внизу панели** (маленький текст под формой ввода):
    ```
    Контекст: 4,250 / 8,000 токенов (~53%)
    ```
  - При приближении к 80% → жёлтый цвет, при 100% → красный

#### 7.6 Провайдер недоступен
- Ответ `503 Service Unavailable`
- **Нижняя строка**: `🔴 Ассистент недоступен` (розовый фон)
- **AI-панель**: красное сообщение: "🔴 Провайдер ассистента недоступен. Попробуйте позже."

#### 7.7 Контекст + запрос слишком большие
- Проверка на бэкенде: если (контекст + промпт + запрос) > максимума провайдера:
  1. Сначала обрезать текст рукописи (оставить последние N% сцен)
  2. Если ещё не хватает — сообщить пользователю и отказать
- **Не** обрезать Кодекс (персонажи/локации) — они существенны для консистентности
- **Не** обрезать Заметки полностью, но можно сократить
- **Нижняя строка**: `⚠️ Контекст обрезан: 25 из 45 сцен` (жёлтый фон)
- **AI-панель**: сообщение в диалоге с рекомендацией

#### 7.8 Логирование
- Все ошибки и предупреждения логировать на бэкенде с трейсом: время, пользователь, провайдер, текст ошибки
- На фронтенде показывать дружелюбное сообщение, не технический стек ошибок

### 8. Undo/Redo (интеграция с AI-операциями)

**Задача:** все действия AI (вставка текста в поле, замена выделения, добавление в курсор) должны быть отменяемы через Undo/Redo. Это не новая система, а интеграция AI-операций в существующий Undo/Redo стек приложения.

#### 8.1 Кнопки в верхней панели

Добавить две кнопки в `.topbar` (левее гамбургер-меню или справа):
```
[↶ Отменить] [↷ Повторить]
```

- **Иконки**: ↶ (U+21B6) для Undo, ↷ (U+21B7) для Redo
- **Состояния**:
  - Disabled (серые), если нет действий для отмены/повтора
  - Active (чёрные), если есть действия
- **Горячие клавиши**:
  - Undo: `Ctrl+Z` (Win/Linux) или `Cmd+Z` (Mac)
  - Redo: `Ctrl+Shift+Z` или `Ctrl+Y` (Win/Linux), `Cmd+Shift+Z` (Mac)

#### 8.2 Выпадающий список истории действий

При клике на кнопку **Undo** или **Redo** — показать листаемый список последних действий:

```
Отмена:
  ▼ Вставлен текст от AI в "Аннотация книги"        [2 мин назад]
  • Отредактирована Аннотация                         [5 мин назад]
  • Добавлена новая Сцена "Встреча"                  [8 мин назад]
  • Изменён статус Сцены на "Done"                   [12 мин назад]
  ...
```

- Клик на действие → откатываемся ровно на это действие (не только на одно шагом, а на выбранное)
- Стрелка ▼ показывает текущую позицию в истории (всё выше можно отменить, всё ниже можно повторить)
- **Максимум в истории:** 50 последних действий
- **Действия, которые записываются в Undo:**
  - Все редактирования текста в редакторе (сцены)
  - Все редактирования полей форм (название книги, аннотация, описание персонажа и т.д.)
  - **Вставки текста от AI** (как отдельные действия)
  - Создание/удаление элементов (сцены, персонажи, локации)
  - Изменение структуры (перемещение сцен, переименование глав)
- **Не записываются:**
  - Простой клик/выделение (без изменения)
  - Прокрутка
  - Открытие/закрытие панелей

#### 8.3 Интеграция с AI-вставками

Каждая операция вставки текста от AI — **отдельное действие в Undo**, не объединяется с предыдущим редактированием:

- **Действие:** `InsertAIText`
  - `type`: "replace-field" | "replace-selection" | "insert-at-cursor"
  - `fieldId`: ID поля (для форм) или `SCENE.id` (для редактора)
  - `originalText`: исходный текст (для отката)
  - `newText`: текст от AI
  - `timestamp`: когда произошла вставка
  - `role`: какая роль ассистента сгенерировала
  - `scope`: масштаб запроса ("field", "scene", и т.д.)

Пример в истории: `🤖 Вставлен текст от Редактора в "Аннотация книги"`

## Точки расширения (Фаза 2 и позже)

**AI-специфичные:**
1. **Multi-model**: выбор модели per-role (уже поле в таблице `AI_ROLE`, структура готова)
2. **Персистентность истории диалогов**: сейчас в памяти, потом — в таблице `AI_CONVERSATION` + `AI_MESSAGE` с сохранением истории между сессиями
3. **Новые типовые запросы**: пользователь может добавлять свои типовые запросы для любого поля формы (расширение `AI_FIELD_PROMPTS`)
4. **Умные типовые запросы**: ассистент анализирует заполненные поля и предлагает релевантные запросы ("А может добавить конфликт персонажу?" если персонаж только что создан)
5. **RAG**: эмбеддинги, поиск релевантных фрагментов вместо полного контекста (если контекст становится проблемой)
6. **Долгие разговоры**: сворачивание старых сообщений в резюме (tokens-saving)
7. **Синхронизация типовых запросов**: шаблоны типовых запросов могут загружаться из облака, делиться между авторами (Фаза 3)
8. **Интеграция с другими провайдерами**: Mistral, Claude.ai (веб-версия), локальные модели (LLaMA)

**Undo/Redo (опционально — отдельный спринт или встраивается одновременно):**
- **Полная система Undo/Redo для всех действий в приложении** (не только AI):
  - История в памяти (Фаза 1) → потом в БД (Фаза 2) с сохранением между сессиями
  - Группировка действий (например, несколько быстрых редактирований текста → одно действие)
  - Ветвление истории (если откатились и сделали новое действие, старая ветка сохраняется, можно вернуться)
  - Горячие клавиши и выпадающий список уже описаны в разделе 8
