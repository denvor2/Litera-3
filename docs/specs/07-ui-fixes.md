## Обзор

Спринт 6 успешно завершил миграцию на PostgreSQL и soft-delete, но UI не был обновлен. Тестирование выявило 2 критичных краша и множество orphan компонентов, которые не подключены в дерево рендера. Спринт 7 — полная UI доработка перед деплоем.

## Критичные баги (БЛОКЕРЫ)

### 1. КРАШ: Корзина роняет всё приложение

**Где:** `frontend/src/components/Sidebar.tsx` функция `loadTrash()` и рендер корзины (строки 59-73, 382-411)

**Проблема:** 
- Backend `GET /api/trash/:projectId` возвращает сгруппированный объект: `{ books: [...], chapters: [...], scenes: [...], codexEntries: [...] }`
- Frontend ожидает плоский массив: `TrashItem[]`
- При клике на КОРЗИНА вызывается `.map()` на объекте → TypeError
- Нет error boundary в `App.tsx` → вся страница падает в белый экран

**Решение:**
1. В `loadTrash()` распарсить ответ и создать плоский массив из всех категорий:
   ```typescript
   const items: TrashItem[] = [
     ...data.books.map(b => ({ type: 'book', id: b.id, title: b.title })),
     ...data.chapters.map(c => ({ type: 'chapter', id: c.id, title: c.title, bookId: c.bookId })),
     ...data.scenes.map(s => ({ type: 'scene', id: s.id, title: s.title, bookId: s.chapter?.book?.id })),
     ...data.codexEntries.map(e => ({ type: 'codexentry', id: e.id, title: e.name }))
   ]
   setTrashItems(items)
   ```

2. Добавить error boundary в `App.tsx` (обёртка вокруг `&lt;Sidebar&gt;`):
   ```typescript
   class ErrorBoundary extends React.Component {
     componentDidCatch(error) { console.error(error); this.setState({ error }) }
     render() { if (this.state?.error) return <div>Ошибка. Перезагрузите.</div>; return this.props.children }
   }
   ```

### 2. Экспорт исключает DONE-сцены (перевёрнут фильтр)

**Где:** 
- `backend/src/services/docxExport.ts:108`
- `backend/src/services/fbExport.ts:94`
- `backend/src/services/pdfExport.ts:73`

**Проблема:** фильтр `if (scene.status === 'DRAFT' || scene.status === 'EDITING')` исключает готовые сцены. Пользователь помечает главу готовой → в экспорте её нет.

**Решение:** либо убрать фильтр (экспортировать ВСЕ сцены), либо оставить с условием `status !== 'DELETED'` (если когда-то будет отдельный статус удаления). По логике: если сцена в рукописи и не удалена — должна быть в экспорте, независимо от статуса.

### 3. Контраст WCAG AA провален на --ink-muted

**Где:** `frontend/src/index.css:8` токен `--ink-muted: #9C9891`

**Проблема:** контраст на белом фоне = 2.87:1, норма AA = 4.5:1. Заголовки секций аккордеона, счётчики слов, вся статистика нечитаема.

**Решение:** затемнить токен до `#6B6862` (текущее значение `--ink-2`) или переименовать все классы `*-muted` на `*-secondary` и привязать к `--ink-2`.

## Не-orphan баги

### 10. Редактирование заголовка сцены теряется при сохранении

**Где:** `frontend/src/components/SceneEditor.tsx:111` — `&lt;h1 contentEditable&gt;`

**Проблема:** заголовок редактируется в UI, но при автосохранении не отправляется на бэкенд.

**Решение:** добавить обработчик `onBlur` или `onInput` и отправлять `PUT /api/scenes/:id { title: newTitle }`.

### 11. Гамбургер-меню мёртвое

**Где:** `frontend/src/App.tsx:357-362`

**Проблема:** пункты «Импорт / История версий / Руководство / Настройки» это `&lt;div&gt;` без `onClick`.

**Решение:**
- Импорт: открыть диалог выбора файла + парсинг (не в Фазе 0, можно заменить на disabled с лейблом)
- История версий: открыть боковую панель версий (не в Фазе 0)
- Руководство: открыть страницу помощи (может быть мне через URL)
- Настройки: открыть `SettingsDialog` с глобальными параметрами

На Фазе 0 можно оставить заглушки с бейджем «скоро» или скрыть.

### 12. Несогласованность данных Codex (String vs Json)

**Где:** `backend/prisma/schema.prisma` и данные в БД

**Проблема:** старые записи Codex имеют `attributes` как JSON-строку, новые — как нативный объект. Frontend ломается при попытке редактировать старые.

**Решение:** 
- Написать миграцию Prisma или SQL скрипт для конвертации всех старых String-атрибутов в Json
- Проверить что все новые записи создаются как объект (они уже так создаются)

### 13. Заметки — заглушка без функционала

**Где:** `frontend/src/components/Sidebar.tsx:368`

**Проблема:** `&lt;textarea&gt;` без `value`/`onChange`/сохранения. Текст теряется при перезагрузке.

**Решение:** 
- На Фазе 0: либо удалить, либо сделать работающий локальный `localStorage` для черновика
- На Фазе 1: хранить заметки в БД как отдельную сущность `ProjectNote`

### 14. Правая панель AI-помощники — статичная

**Где:** `frontend/src/App.tsx:430-466`

**Проблема:** чипы ролей и кнопки ⚙ не реагируют, это просто макет. «Будет доступна в следующей версии».

**Решение:** на Фазе 0 это приемлемо (макет оставлен для будущего). Можно добавить `disabled` стиль и бейдж «будет в Фазе 2».

### 15. Дизайн-несогласованность Кодекс компонентов

**Где:** `frontend/src/components/CodexList.css`, `CodexForm.css`, `CodexPanel.css`

**Проблема:** используют Material-палитру (`#1976d2`, `#d32f2f`), а не авторскую (`--accent`, `--border`).

**Решение:** переписать CSS на токены авторской палитры перед подключением компонента (или заменить на новый компонент в авторском стиле).

### 16. Resize-handle спозиционирован неверно

**Где:** `frontend/src/App.tsx:412-429` и `frontend/src/App.css:190-204`

**Проблема:** хэндл позиционирован у левого края воркспейса, а не на границе центра и правой панели. Пользователь не может ухватить край интуитивно.

**Решение:** переспозиционировать на границу правой панели (через grid-column или `right: calc(var(--right-w) - 6px)`).

### 17. Тёмная тема ломается в SceneEditor

**Где:** `frontend/src/components/SceneEditor.css` строки 162-186 (жёсткие светлые цвета)

**Проблема:** `.scene-notes`, `.scene-versions` и другие имеют `background-color: #f9f9f9`, что в тёмной теме — почти белый на тёмном.

**Решение:** заменить на `var(--surface)`, `var(--surface-2)`, `var(--border)` в зависимости от слоя.
