# Спринт 7б — Редактирование элементов Sidebar

## Пункты 3-8 из пункта плана

### 3. Глава — ✎ открывает форму переименования
- При клике на ✎ рядом с названием главы
- Открывается форма в центральной зоне (`.center-card` с полем название)
- Сохранение отправляет PUT `/api/chapters/:chapterId` с новым названием
- После сохранения дерево обновляется

### 4. Сцена — ✎ открывает форму редактирования
- При клике на ✎ рядом с названием сцены
- Форма содержит: название, статус (draft/editing/done), POV (выпадающий список персонажей), локация
- PUT `/api/scenes/:sceneId` с обновленными полями
- После сохранения обновляется список и редактор

### 5. Персонажи (Кодекс) — ✎ редактирует
- Клик на ✎ на чипе персонажа открывает форму редактирования
- Форма редактирует `name` и `attributes` (TipTap JSON)
- PUT `/api/codex/:entryId`
- После сохранения обновляется список в Кодексе

### 6. Локации (Кодекс) — ✎ редактирует
- Аналогично пункту 5, но для типа `location`
- Поля: название и описание (TipTap)

### 7. Заметки — сохраняются
- Textarea в секции ЗАМЕТКИ автосохраняется
- Дебаунс 2 сек после последнего изменения
- PUT `/api/scenes/:sceneId` с полем `notes`
- Индикатор сохранения как в редакторе

### 8. Корзина — счётчик удалённых элементов
- Бейдж с числом рядом с "КОРЗИНА" (как в мокапе, строка 304)
- Обновляется при удалении элемента

## Backend требования
- PUT `/api/chapters/:chapterId` — обновить название
- PUT `/api/scenes/:sceneId` — обновить название, статус, POV, локация, notes
- PUT `/api/codex/:entryId` — обновить name и attributes

## UI требования
- Формы редактирования в центральной зоне (не инлайновое)
- После сохранения — вернуться в режим просмотра или к редактору
- Обработчики ошибок (показ сообщения об ошибке)

## Тестирование
- После каждого исправления пункта 3-8 запустить ui-reviewer
- Отметить ✅/❌ для каждого
