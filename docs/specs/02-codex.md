# Модуль «Кодекс» — Фаза 0 (базовый)

Источник: п. 3.3–3.4 исходного ТЗ, сокращено до MVP.

## Типы сущностей в Фазе 0
Только `character` и `location`. Поле `type` в БД — строка, не enum (см. `../data-model.md`) — так Фаза 2 добавит `object`, `faction`, `language` и т.д. без миграции схемы, только добавлением новых значений и соответствующих полей формы на фронте.

## Карточка персонажа (character) — поля в MVP
- name: string, обязательно
- appearance: text, опционально (внешность)
- personality: text, опционально (характер)
- goal_conflict: text, опционально (цель/конфликт)

Всё остальное из 3.3.1 (арка развития, граф отношений) — Фаза 2, требует RELATIONSHIP-таблицы.

## Карточка локации (location) — поля в MVP
- name: string, обязательно
- description: text, опционально

Вложенность локаций (страна → город → здание, 3.4.1) — Фаза 2.

## Автотрекинг появлений (3.3.2)
- MVP: список сцен, где сущность упомянута (через SCENEENTITYLINK), строится автоматически при сохранении сцены — парсинг текста на точные совпадения имени
- POV отдельно помечается на карточке сцены (см. 01-manuscript.md), не парсится из текста

## Доступ из сайдбара при письме
- В режиме письма должна быть возможность открыть карточку Кодекса, не выходя из текста (боковая панель или модальное окно — на усмотрение UI-спринта, зафиксировать решение в UI-спеке фронта при реализации)

## Явно не в Фазе 0
- Поле "changes over time" (3.3.3, привязка состояния к таймлайну)
- Объекты/артефакты/фракции/языки, кастомные типы
- Карты с пинами
- Глоссарий/вики со связями между статьями (кроме уже существующего SCENEENTITYLINK)
