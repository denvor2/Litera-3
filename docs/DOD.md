# Definition of Done — LitStudio 2

Каждый спринт закрывает 1–3 пункта из конкретного файла в `docs/specs/`. Спринт не считается закрытым, пока не пройдены все пункты ниже — по порядку, каждый блокирует следующий.

## 1. Архитектор (соответствие ТЗ)
Проверяет `.claude/agents/architect.md`. Сверяет реализованное с конкретным пунктом спеки (не с ТЗ целиком — со спекой модуля).
- [ ] Каждый пункт спеки, взятый в спринт, реализован ровно так, как написан acceptance-критерий (не "примерно так")
- [ ] Ничего не реализовано сверх спринта (никаких "заодно добавил X из Фазы 2")
- [ ] Все явные "точки расширения", отмеченные в спеке, действительно оставлены расширяемыми (не захардкожены так, что Фаза 2 потребует переписывания)
- [ ] Модель данных совпадает с `docs/data-model.md`; любое расхождение — сначала правка data-model.md, потом код

Блокирует мердж: да.

## 2. Контроль качества кода
Проверяет `.claude/agents/code-quality.md`.
- [ ] Нет дублирования логики, уже существующей в другом модуле (валидация, форматирование счётчиков слов, парсинг сущностей и т.п. — искать общие утилиты)
- [ ] Именования и структура файлов согласованы с уже существующим кодом проекта
- [ ] Нет противоречий между модулями (например, два разных места считают а.л. по-разному)
- [ ] Есть тесты на новую логику (см. пункт 4)
- [ ] Нет закомментированного кода, TODO без тикета, console.log/debug-мусора

Блокирует мердж: да.

## 3. UI-ревью
Проверяет `.claude/agents/ui-reviewer.md`. Только если спринт трогал интерфейс.
- [ ] Соответствие мокапам (десктоп/таблет/мобильный, где применимо)
- [ ] Состояния: пустое, загрузка, ошибка, длинный текст/много данных — не только happy path
- [ ] Клавиатурная доступность базовых действий (создать сцену, сохранить, drag-n-drop имеет альтернативу для клавиатуры)

Блокирует мердж: да, если менялся UI. Не блокирует чисто бэкенд-спринты.

## 4. Тестировщик
См. `.claude/agents/tester.md` и скилл `litstudio-testing`.
- [ ] Автотесты на модель данных и API нового модуля (минимум: happy path + одна граничная ситуация на каждый эндпоинт)
- [ ] Все существующие тесты проходят (регрессия)
- [ ] Ручной прогон сценария из user story (раздел 4 исходного ТЗ), относящегося к спринту

Блокирует мердж: да.

## 5. Финальный статус
После прохождения всех четырёх — спринт помечается закрытым. Между спринтами — одно уведомление: что сделано, что заблокировано (если есть), что в следующем спринте. Без вопросов и подтверждений в процессе спринта (см. CLAUDE.md).
