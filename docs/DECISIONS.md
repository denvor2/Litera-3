## 2026-07-22 Спринт 5 — UI polish

### SQLite вместо PostgreSQL

**Вопрос:** какую БД использовать для Фазы 0?

**Решение:** SQLite (файл `dev.db`) вместо запланированного PostgreSQL.

**Почему:** ускорение локальной разработки, упрощение деплоя на этапе прототипирования, единая `.db` файл без настройки сервера.

**Последствия:** 
- `Prisma Json` тип недоступен → String с ручным JSON.stringify/parse
- `mode: 'insensitive'` в queries недоступен
- Миграция на Postgres потребует конвертации String → Json

### String вместо Json для body, attributes, snapshot

**Вопрос:** как хранить структурированные данные в SQLite?

**Решение:** `Scene.body`, `CodexEntry.attributes`, `Version.snapshot` как String (JSON-serialized).

**Почему:** SQLite Prisma-провайдер не поддерживает Json тип; String совместим с миграцией на Postgres позже.

**Последствия:** требует JSON.parse на read, JSON.stringify на write; граница сериализации в приложении, требует типизации.

### Centralize API URLs

**Вопрос:** как управлять API хостом при разных окружениях?

**Решение:** `API_BASE` константа из env или дефолт `http://localhost:3000`.

**Почему:** упрощить изменение при деплое, избежать дублирования жёстких URL.

## 2026-07-22 Спринт 6 — PostgreSQL миграция

### Возврат к PostgreSQL и JSONB типам

**Вопрос:** продолжить на SQLite с String-сериализацией или перейти на PostgreSQL?

**Решение:** Возвращение к PostgreSQL с нативными Json (JSONB) типами для `body`, `attributes`, `snapshot`.

**Почему:** SQLite требует ручного JSON.stringify/parse при каждой операции, усложняет код и медленнее. PostgreSQL JSONB позволяет индексировать и запрашивать структуру в БД, упрощает приложение, даёт место для оптимизаций на Фазе 2.

**Последствия:** 
- Новая миграция чистая инициализация (нет конвертации Sprinт 5 данных, т.к. они были тестовые)
- Удаление JSON.stringify/parse из всего кода
- Обновление data-model.md

### Мягкое удаление (soft-delete) в Фазе 0

**Вопрос:** реализовать корзину в Фазе 0 или отложить на Фазу 2?

**Решение:** Мягкое удаление и корзина реализованы в Фазе 0. Все таблицы имеют `deleted_at DateTime?`, DELETE → UPDATE с временной меткой.

**Почему:** Кнопка 🗑 уже видна в UI, пользователь ожидает функцию. Soft-delete — простой и безопасный паттерн, добавляет минимум overhead. Лучше закончить в Фазе 0, чем оставить зависшую кнопку.

**Последствия:** 
- Все READ запросы фильтруют `deleted_at IS NULL`
- Endpoints GET /api/trash/:projectId и PUT /api/trash/*/restore
- Frontend UI в Sidebar показывает удалённые элементы и кнопку восстановления

### Миграция БД — инициализация без конвертации

**Вопрос:** как перенести данные из SQLite в PostgreSQL?

**Решение:** Миграция создаёт таблицы с нуля, без скрипта конвертации String → Json.

**Почему:** Спринты 5–6 — прототипная разработка, нет прод-данных для переноса. Для MVP чистая инициализация — приемлемо. Реальная миграция (если появятся данные) будет спланирована отдельно.

### RFC 5987 для Content-Disposition с кириллицей

**Вопрос:** как передать кириллическое имя файла в HTTP header?

**Решение:** `Content-Disposition: attachment; filename*=UTF-8''%d0%92%d0%be%d0%b9%d0%bd%d0%b0.docx` (RFC 5987 percent-encoded UTF-8).

**Почему:** Стандартные Content-Disposition с Cyrillic символами невалидны по HTTP. RFC 5987 — стандартный способ, поддерживается всеми современными браузерами.

### Шрифты для PDF экспорта с кириллицей

**Вопрос:** как отобразить русский текст в PDF?

**Решение:** Использование системных шрифтов (Arial на Windows, DejaVuSans на Linux) вместо встроённого Helvetica.

**Почему:** Helvetica кодирует только ASCII/Latin-1. Arial и DejaVuSans поддерживают полный Unicode с кириллицей. Fallback на Helvetica, если шрифт недоступен (теряет кириллицу, но не крашится).

### TipTap ноды в camelCase и snake_case

**Вопрос:** почему текст в списках теряется при экспорте?

**Решение:** Parser `extractTextFromTipTap` теперь распознаёт оба формата: camelCase (`bulletList`) и snake_case (`bullet_list`).

**Почему:** TipTap StarterKit сериализует в camelCase, но legacy-данные или конвертированные структуры могут быть snake_case. Поддержка обоих гарантирует сохранение текста.

**Последствия:** 
- Исправлен баг молчаливой потери текста в списках
- Тестирование экспорта и поиска (fb2, pdf, search)

### Типовые запросы как компактные чипсы вместо full-width кнопок

**Вопрос:** реализовать типовые запросы (quick prompts) под каждой ролью в AI-панели — как в мокапе (full-width кнопки 8px) или как компактные чипсы?

**Решение:** Компактные чипсы (inline-flex, flex-wrap, border-radius: 14px, padding: 6px/9px) вместо full-width кнопок.

**Почему:** 
- UX: чипсы визуально согласуются с ролями и масштабами (единое семейство компонентов с `--radius: 14px`)
- Компактнее: на панели 200–280px full-width кнопки создают ощущение пустоты; чипсы эффективнее используют пространство
- Запросы обычно 30–50 символов — для them чипсовая форма оптимальнее, чем full-width

**Отклонение от мокапа:** `design/mockup/index.html` показывает full-width кнопки (8px, 100% ширина панели, переносится текст внутри). Решение — осознанное отклонение ради лучшей UX.

**Исправленный баг:** убран `white-space: nowrap` (обрезал текст запросов на узких панелях < 230px); добавлен `max-width: 200px` + `word-wrap: break-word` для переноса текста внутри чипа при нехватке места.

**Файлы:**
- `frontend/src/components/AIPanel.css` (`.quick-btn`, строки 150–176)
- `frontend/src/components/AIPanel.tsx` (рендер типовых запросов с flex-wrap контейнером)

**Если нужно вернуть к мокапу:** переделать на full-width `display: block; width: 100%`, убрать flex-wrap контейнер, вернуть `border-radius: 8px` (var(--radius)).

## 2026-07-24 Спринт 11 — Auth Integration

### JWT в httpOnly cookies вместо localStorage

**Решение:** JWT token передается в httpOnly cookie, не хранится в localStorage.

**Почему:** httpOnly защищает от XSS атак (JavaScript не может украсть cookie). 7-день expiry в cookie и JWT payload.

**Как:** 
- Backend: `fastify.register(cookiePlugin)`, `reply.setCookie('auth_token', token, { httpOnly: true, secure: NODE_ENV==='production', sameSite: 'lax' })`
- Frontend: `fetch(..., { credentials: 'include' })` передаёт cookie автоматически
- Backend: `verifyToken(request.cookies.auth_token)` проверяет JWT

**Файлы:**
- `backend/src/services/authService.ts` (login, register, verifyToken)
- `backend/src/index.ts` (auth endpoints + cookie setup)
- `frontend/src/App.tsx` (checkAuth, handleLogout)

### CORS с явным allowlist вместо origin: true

**Решение:** CORS настроен на explicit allowlist origins вместо отражения Origin header.

**Почему:** Предотвращает CSRF/cross-origin атаки. `origin: true` с `credentials: true` позволял любому сайту делать credentialed запросы.

**Как:** 
```javascript
const allowedOrigins = process.env.ALLOWED_ORIGINS?.split(',') || [
  'http://localhost:5173', 'http://localhost:5174', 'http://127.0.0.1:5173', 'http://127.0.0.1:5174'
]
fastify.register(cors, { origin: allowedOrigins, credentials: true })
```

**Файлы:** `backend/src/index.ts:19-29`

### JWT_SECRET: fail-fast в production без hardcoded fallback

**Решение:** Если JWT_SECRET не задан в окружении и NODE_ENV==='production', приложение падает при старте.

**Почему:** Hardcoded fallback 'dev-secret-key-change-in-production' позволял бы кому-то подделать токен в production. Лучше упасть явно, чем молча использовать небезопасный дефолт.

**Как:**

```javascript
const JWT_SECRET = process.env.JWT_SECRET

  throw new Error('JWT_SECRET environment variable must be set in production')
}
```

### Auth guard на все /api/* routes

**Решение:** Глобальный `addHook('preHandler')` требует валидный JWT token для всех /api/* endpoints.

**Почему:** Защита данных от неавторизованного доступа. Без этого API был открыт для любого, кто знает URL.

**Как:**
```javascript
const requireAuth = async (request, reply) => {
  const token = request.cookies.auth_token
  if (!token) reply.code(401).send({ error: 'Not authenticated' })
  const payload = await verifyToken(token)
  request.userId = payload.userId
}

fastify.addHook('preHandler', async (request, reply) => {
  if (request.url.startsWith('/api/')) await requireAuth(request, reply)
})
```

**Файлы:** `backend/src/index.ts:38-52`

### Регрессия кодировка UTF-8 в JSON ответах

**Проблема:** Текст на кириллице отображался как "????????" (mojibake), HTML заголовок `<meta charset="UTF-8">` не помогал.

**Решение:** Добавлен глобальный hook в backend который устанавливает правильный Content-Type для всех JSON ответов:
```javascript
fastify.addHook('onSend', async (request, reply) => {
  reply.header('Content-Type', 'application/json; charset=utf-8')
})
```

**Почему:** Браузер полагается на Content-Type header из ответа, а не только на meta charset в HTML. Без явного charset в header браузер может некорректно декодировать JSON.

**Файлы:**
