# UI-спека Фазы 0 — привязка к мокапу

Файл `index.html` в этой папке — не референс "для вдохновения", а буквальный макет структуры и состояний. Открой его в браузере (просто открыть файл, зависимостей нет). Вкладки сверху переключают две демонстрации: основной десктопный экран и мобильный экран. Карточка Кодекса и карточка книги — не отдельные вкладки, они встроены прямо в центральную зону основного экрана (см. ниже) — открой «Рабочее пространство» и кликни по чипу в Кодексе или по ✎ на строке книги, чтобы увидеть их вживую, включая переключение обратно.

**Правило:** структура (что где расположено, какие есть блоки, какие состояния у каждого элемента) — обязательна к реализации именно так. Пиксельные значения (отступы, конкретные hex-цвета) — ориентир, не сакральны; если у тебя уже есть токены дизайн-системы в коде, используй их, но с той же логикой.

## Экран 1 — «Рабочее пространство» = единственный основной экран приложения
Соответствует `docs/specs/01-manuscript.md` + `docs/specs/02-codex.md`. Отдельного «режима письма» как самостоятельного экрана нет — есть переключатель полноэкранного текста внутри этого же экрана (см. ниже).

Раскладка: левая зона / центр / правая зона / нижняя полоса. Зоны — не равнозначные колонки, у каждой своя роль:

### Левая зона — «вся коллекция» (аккордеон)
Над аккордеоном — переключатель серии/книги: название текущей серии (не редактируется прямо тут — редактирование серии через Настройки, гамбургер-меню) + выпадающий список книг этой серии + кнопка «+ новая книга». Выбор книги в этом select перестраивает содержимое секции «Рукопись» ниже (дерево глав/сцен относится только к выбранной книге), но не трогает секцию «Кодекс» — Кодекс общий на всю серию, не на книгу (см. `docs/specs/01-manuscript.md`).

Ниже — одна вертикальная панель со сворачиваемыми секциями. **Аккордеон эксклюзивный**: открыта ровно одна секция, при открытии любой другой предыдущая автоматически схлопывается (в мокапе — JS на событие `toggle` у `<details>`, закрывает остальные; в реальном UI — любой аккордеон-компонент с таким же поведением). Всегда должна оставаться открытой хотя бы одна секция — закрыть последнюю открытую нельзя, попытка снова её раскрывает (в мокапе это тоже обработано).
- **Рукопись** — дерево Книга → Глава → Сцена (то, что раньше было отдельным сайдбаром). Открыта по умолчанию.
- **Кодекс** — персонажи и локации как чипы, сгруппированные подзаголовками. Клик по чипу открывает карточку сущности **в центральной зоне**, не в модалке поверх экрана (см. «Центр» ниже — важное изменение по сравнению с прошлой версией спеки).
- **Заметки** — поле заметок для *текущей открытой сцены* (не общий список по всей книге — привязка к сцене, как и было в исходной спеке, просто теперь это секция аккордеона, а не отдельный блок правой панели).
- **Корзина** — список удалённых элементов (сцен, сущностей Кодекса — что угодно, что можно удалить) с кнопкой «восстановить» на каждом. Пустое состояние — просто текст «Корзина пуста», без иллюстраций.

Важно для реализации: удаление любого элемента (сцены, персонажа, локации, главы) в Фазе 0 **всегда мягкое** — элемент помечается удалённым и уходит в Корзину, а не стирается из БД сразу. Окончательное удаление (опционально, можно не делать в Фазе 0) — отдельное действие уже из самой Корзины.

### Действия: добавить / редактировать / в корзину
Единый паттерн для всех элементов левой зоны, кроме самой серии (см. исключение ниже).

- На каждой строке (книга, глава, сцена, персонаж, локация) при наведении справа появляются две иконки: ✎ редактировать, 🗑 удалить (в мокапе — CSS `display:none` → `flex` по `:hover`; на мобильном, где hover нет, эти же действия — через свайп или долгое нажатие, выбрать способ в мобильном UI-спринте).
- ✎ — открывает форму настроек элемента в центральной зоне (не инлайн-переименование — единый паттерн для всех уровней, см. «Центр» ниже: у книги, главы, сцены, серии, персонажа и локации это одна и та же механика, просто с разным набором полей). Это отдельное действие от обычного клика по строке: клик по сцене или главе **не** открывает настройки, а переходит к тексту (разворачивает сцену или скроллит к главе, см. «Центр»); клик по персонажу/локации — тоже открывает карточку Кодекса, так что для них ✎ и обычный клик ведут к одному и тому же виду (это нормально, у Кодекса нет отдельного «режима чтения» карточки в Фазе 0).
- 🗑 — сразу отправляет элемент в Корзину (мягкое удаление). **Без модального подтверждения** — раз удаление обратимо через Корзину, лишний confirm-диалог на каждый клик не нужен, это осознанное решение, не упущение.
- Добавление — текстовая ссылка «+ добавить …» внизу соответствующего списка (сцена — под сценами главы, глава — под всеми главами книги, книга — под списком книг серии, персонаж/локация — под каждой из этих групп в Кодексе). Один и тот же визуальный паттерн на всех уровнях.

**Исключение — Серия.** У строки серии есть только ✎ (переименовать), без 🗑 — удаление всей серии со всеми книгами внутри слишком разрушительное действие для однокликового hover-удаления, даже мягкого. Вынесено в Настройки (гамбургер-меню), где можно сделать более заметное предупреждение перед таким действием.

### Центр — переключаемые виды, панели вокруг не закрываются
Центр — не только редактор. Это зона с несколькими видами, которые сменяют друг друга **внутри тех же границ**, не трогая левую и правую зоны, гамбургер-меню и нижнюю полосу. Смысл: любая карточка/форма настроек открывается не поверх всего экрана, а на месте текста — потому что AI-помощники справа и остальная коллекция слева часто нужны именно в момент редактирования (например, спросить Соавтора про формулировку синопсиса, или свериться по дереву сцен, есть ли уже персонаж с похожим именем, пока заполняешь карточку). Закрывать для этого весь экран — терять контекст, который в этот момент как раз нужен.

Виды (в мокапе — `#centerEditor`, `#centerCodexCard`, `#centerBookCard`, `#centerChapterCard`, `#centerSceneCard`, `#centerSeriesCard`, `#centerAssistantCard`, показывается только один через `display`, переключение — `showCenterView(view)`):

#### 1. Редактор — единый текст книги, не изолированные сцены
Клик по книге, главе или сцене в левой зоне не заменяет какой-то один «текущий текст» на другой изолированный — вся книга в редакторе представлена как **непрерывный поток**: главы идут одна за другой (разделитель — заголовок главы), сцены внутри — сворачиваемые блоки. **По умолчанию развёрнута ровно одна сцена** (заголовок + статус/POV/локация + тулбар + сам текст), остальные показаны свёрнуто — только заголовок, точка статуса и счётчик слов в одну строку, кликабельно.

- **Клик по сцене в левой зоне** — сворачивает предыдущую развёрнутую сцену, разворачивает выбранную и скроллит центр к ней (`scrollIntoView`). Это то же самое действие, что и клик прямо по свёрнутому заголовку сцены в центре — оба ведут к одному и тому же состоянию.
- **Клик по главе в левой зоне** — скроллит центр к разделителю этой главы, не трогая состояние развёрнутости сцен (не разворачивает и не сворачивает ничего сам по себе — просто перемещает к месту в потоке).
- **«Развёрнуть всю книгу» / «Свернуть до одной сцены»** — ссылка над текстом (`.ms-flow-toggle` в мокапе). Разворачивает сразу все сцены потока — это осознанное исключение из «одна сцена за раз», добавленное для сценария «перечитать несколько сцен подряд, проверить, не потерялась ли нить». Одна сцена — режим по умолчанию для активного письма (меньше визуального шума), полный разворот — режим для вычитки. Переключение вручную, не автоматическое.
- **Статус сцены — редактируется прямо в развёрнутом виде** (select в строке метаданных), не только через форму настроек — это самое частое действие при письме (пометить сцену готовой), прятать его за лишним переходом было бы неудобно. POV, локация, целевой объём и переименование — по-прежнему только через ✎ (форма настроек, вид 5) — эти поля меняются заметно реже.
- Это не «единый безразмерный текст без структуры» — просто единый скролл вместо переключения между полностью изолированными экранами на каждую сцену. Реализационно это по-прежнему отдельные записи `SCENE` с отдельным сохранением текста каждой (см. `docs/data-model.md`) — на уровне данных ничего не меняется, меняется только то, как это представлено в интерфейсе редактора.
- **Клик по упоминанию** (`.mention`) переключает центр на карточку Кодекса этой сущности (вид 2), а не на сцену — здесь единственное исключение из «всё в одном потоке».
- Индикатор сохранения и счётчики здесь не показываются — они в нижней полосе, общей для всего экрана, и относятся к той сцене, что сейчас развёрнута (при полном развороте всех сцен — к последней, на которой стоял фокус, это не идеальное поведение для полностью общего случая, но для Фазы 0 достаточно, полный разворот — вспомогательный режим для чтения, не основной режим письма).

#### 2. Карточка Кодекса
Открывается кликом по чипу в левой зоне, по упоминанию в тексте, или по ✎ на чипе. Поля — как в `docs/specs/02-codex.md` (внешность/характер/цель-конфликт для персонажа), редактируемые (`textarea`). Блок «появляется в сценах» — автотрекинг, клик по ссылке возвращает в редактор (вид 1) и разворачивает нужную сцену — то же поведение, что клик по сцене в левой зоне.

#### 3. Карточка книги (настройки параметров)
Открывается по ✎ на строке книги (обычный клик по книге в списке по-прежнему просто переключает текущую книгу — это разные действия). Поля: Название, Серия, Жанр, Плановый объём, Синопсис, Аннотация — подробности ниже.

#### 4. Настройки главы
Открывается по ✎ на строке главы. В Фазе 0 всего одно поле — Название (в модели данных у `CHAPTER` больше пока ничего и нет, см. `docs/data-model.md`). Не выглядит избыточным как отдельная форма ради одного поля — если по факту переименование остаётся единственным действием, инлайн-переименование по клику на ✎ (без ухода в отдельный вид центра) не хуже; решение оставить как отдельную форму сейчас — ради единообразия паттерна с остальными элементами (сцена, персонаж, книга), чтобы не было двух разных способов «редактировать» в одном интерфейсе. Если в Фазе 2 у главы появятся собственные поля (например, эпиграф, заметка автора к главе) — форма уже готова их принять.

#### 5. Настройки сцены
Открывается по ✎ на строке сцены — отдельно от клика по самой сцене (который просто разворачивает её текст, вид 1). Поля: Название, Статус, POV (список персонажей из Кодекса книги), Локация (список локаций), Целевой объём в словах (используется для прогресс-бара в нижней полосе, см. ниже). Это единственное место, где меняется целевой объём — в развёрнутом виде сцены (вид 1) его нет, там только сам текст.

#### 6. Настройки серии
Открывается по ✎ на строке серии в левой зоне (см. «Действия» выше — единственное действие у серии). В Фазе 0 всего одно поле — Название серии.

#### 7. Настройки AI-помощника
**То же правило действия из левой зоны распространяется и на правую** — не только ⚙/добавление у элементов правой панели ведёт к своей форме, но и любой будущий элемент с настройками в интерфейсе должен следовать этому же паттерну (одна общая механика `showCenterView`, а не отдельная для каждой зоны). Открывается по ⚙ на существующей роли (Соавтор/Редактор/Критик/Читатель — заголовок формы показывает «Настройки: <роль>») или по клику на «+ свой» (заголовок — «Новый помощник», поля пустые). Поля: Название, Модель (по умолчанию как у всего проекта, или отдельная — реальный выбор моделей появится вместе с интеграцией LLM в Фазе 2, в Фазе 0 это просто переключатель «своя/общая»), Промпт-инструкция (системное описание роли), Типовые запросы (по одному на строку — те же, что показываются под чипами в правой панели, редактируются здесь же, не отдельным механизмом).

Клик по шестерёнке **не переключает активную роль** (в отличие от клика по самому чипу) — те же два независимых действия на одном компоненте, что уже описаны для чипов в разделе «Правая зона» выше.

### Настройки книги: поля
- **Название** — текстовое поле.
- **Серия — выпадающий список**, не просто отображение (это осознанно другое решение, чем в позапрошлой версии этой спеки, где серия была нередактируемой; теперь можно выбрать любую существующую серию пользователя или «Без серии»). Технически смена серии у книги — это `UPDATE BOOK SET project_id = ...`, при выборе новой серии из списка книга физически переезжает в другой `PROJECT`. Раз это доступно прямо из формы, стоит подсветить выбор нестандартным цветом при отличии от текущего значения (чтобы не уйти со страницы, случайно поменяв книге серию одним лишним кликом по select) — конкретную реализацию такой подсказки оставляю на усмотрение UI-спринта.
- **Жанр — выпадающий список**, категории взяты с классификатора Литрес (Детектив, Триллер, Фантастика, Научная фантастика, Фэнтези, Городское фэнтези, Магический реализм, Young Adult, New Adult, Любовный роман, Женская проза, Современная сказка/ретеллинг — художественная; Нон-фикшен, Автофикшен, Научно-популярная литература — документальная; список в мокапе неполный, взять актуальный полный классификатор с litres.ru при реализации, он может обновляться). На самом Литрес можно указать несколько жанров/тегов на книгу — в Фазе 0 ограничиваемся одним основным полем `genre` (string) в БД, множественный выбор (переход на связку многие-ко-многим с таблицей жанров) можно добавить в Фазе 2 без разрушающих изменений для уже введённых данных.
- **Плановый объём** — свободный текст, не строгое число (единицы у разных авторов разные: кто-то в а.л., кто-то в словах).
- **Синопсис** — рабочий, для себя.
- **Аннотация** — читательская, для обложки/публикации, отдельно от синопсиса — разные тексты с разными целями.

Ссылка «+ добавить поле» внизу формы — визуальный намёк на то, что набор полей не жёстко фиксирован: модель данных уже держит `attributes json` (`docs/data-model.md`) под будущие поля без миграции схемы. **Но сама возможность добавлять произвольные поля через UI — не обязательно Фаза 0**: динамический конструктор полей можно отложить в Фазу 2. Не путать эти два: расширяемость схемы (нужна сейчас) и UI для пользовательских полей (можно позже).

### Правая зона — «AI-помощники»
Ширина панели изменяется перетаскиванием за левый край (в мокапе — `.resize-handle`, 6px, курсор col-resize, диапазон 200–460px, подсвечивается голубым при наведении/перетаскивании тем же `--selected-bg`). Ширину стоит сохранять между сессиями (localStorage на вебе, аналог на десктопе/мобильном) — это уже реализационная деталь, не часть визуального мокапа, но зафиксировать в спринте, где делается эта панель.

Под заголовком — короткая строка о том, что именно видят помощники (`.ai-context-note`): текст текущей книги + Кодекс всей серии. Это не декоративная подпись — отражает реальный скоуп контекста, зафиксированный в `docs/specs/08-ai-experts.md`: Кодекс (персонажи/локации) собирается на уровне серии, текст рукописи, который ассистент читает для ответа, — только на уровне текущей книги, другие книги серии не подмешиваются.

Ниже чипов ролей — отдельный ряд `.ai-scope-row`: Сцена / Глава / Диалог / Выделение. Это **не то же самое**, что контекст выше — контекст (что ассистент знает) всегда «вся книга + Кодекс серии»; масштаб здесь — на какой конкретно фрагмент нацелен именно этот запрос (например, «предложи вариант сцены» относится к масштабу «Сцена», а не ко всей книге). По умолчанию — «Сцена» (текущая развёрнутая). **Выделение текста мышью в теле сцены переключает масштаб на «Выделение» автоматически** — попробуй в мокапе: выдели фразу в тексте, селектор справа сам подсветится, под ним появится усечённая цитата выделенного. Диалог — распознавание диалогового фрагмента, в мокапе просто переключаемый пункт без реальной логики распознавания (это деталь реализации соответствующего спринта).

Панель — вертикальный флекс из четырёх зон сверху вниз, порядок фиксирован:
1. **Чипы ролей.** Соавтор / Редактор / Критик / Читатель + «свой». У каждой существующей роли (не у «+ свой») — своя шестерёнка ⚙ рядом с названием, всегда видима (не только по hover, в отличие от ✎/🗑 в левой зоне — настройки роли не деструктивное действие, прятать не нужно). Клик по шестерёнке открывает настройки конкретного ассистента (промпт-инструкция, при необходимости — выбор модели), не переключает активную роль. Клик по самому чипу — переключает активную роль (голубая заливка, тот же `--selected-bg`, что и везде для «выбрано»).
2. **Типовые запросы выбранного помощника.** Меняются при переключении роли — набор из 3 быстрых запросов, специфичных для роли (например, у Критика — «что не работает в этой сцене», у Читателя — «что я почувствую, читая это впервые»; конкретные формулировки нужно будет проработать содержательно, в мокапе — иллюстративный набор). Клик по любому — отправляет его как обычный запрос (тот же путь, что и ручной ввод).
3. **Область диалога.** Растягивается на всё оставшееся место (`flex:1`, скроллится) — это единственная часть панели с переменной высотой, всё остальное фиксированной высоты по контенту.
4. **Форма запроса — внизу, прижата к нижнему краю панели**, не под диалогом в потоке. Ответ ассистента добавляется в область диалога **над** формой (последнее сообщение оказывается прямо над полем ввода, а не где-то в середине истории выше) — так же, как в любом чат-интерфейсе.

Ролевые предустановленные запросы, сам факт диалога с LLM — визуальная заглушка в Фазе 0 (интеграция с LLM — Фаза 2, `docs/specs/08-ai-experts.md`), но раскладку (расположение зон, фиксированная форма внизу, типовые запросы над диалогом) нужно делать уже сейчас, чтобы потом не перекраивать сетку компонента.

### Нижняя полоса — статистика и статус сохранения
Одна строка на всю ширину экрана под всеми тремя зонами: слева — счётчики (слова / знаки с пробелами / а.л. / страницы, формулы — `docs/specs/07-goals-insights.md`) и рядом с ними прогресс-бар, справа — индикатор сохранения. Общая для экрана, не привязана к какой-то одной зоне визуально, но логически всегда отражает состояние текущей открытой сцены.

- **Прогресс-бар** — от цели по объёму *текущей сцены* (пользователь может задать целевое количество слов на сцену; если цель не задана — прогресс-бар просто не показывается, а не показывается пустым/нулевым). Это не то же самое, что модуль «Цели и статистика» из `docs/specs/07-goals-insights.md` (дневные/недельные цели, стрики, графики — там) — здесь узкий, лёгкий кусок функциональности just для одной сцены, достаточно простой, чтобы делать его в Фазе 0, не дожидаясь всего модуля целиком. Поле цели по сцене — добавить в `SCENE` в `docs/data-model.md` (`target_word_count`, nullable int) при реализации.
- **Индикатор сохранения — теперь с цветной точкой**, не только текстом: зелёная точка = «сохранено», янтарная = «сохраняется…», красная = «ошибка сохранения» (те же цвета, что и у точек статуса сцены в дереве слева — единая цветовая логика на весь интерфейс, не отдельная палитра только для этого индикатора).

### Верхняя панель
- Слева — кнопка-гамбургер, открывает выпадающее меню: Импорт, Экспорт, История версий / откатить, **Руководство**, Настройки. В Фазе 0 реализуются только пункты, которые уже есть в спеках (Экспорт — `docs/specs/03-export.md`; История версий — упрощённое версионирование из `01-manuscript.md`; Руководство — см. ниже); Импорт и Настройки могут быть заглушками до Фазы 2.
- Справа — кнопка «Полноэкранный текст»: скрывает левую и правую зоны, оставляя только центр редактора и нижнюю полосу с сохранением/счётчиками. Это и есть весь «режим письма» — переключение состояния той же сетки, не переход на другой экран/маршрут. Повторный клик возвращает зоны обратно.

#### 8. Руководство
Открывается пунктом «Руководство» в гамбургер-меню — тем же `showCenterView`, что и всё остальное, никакого отдельного модального окна. Содержимое — `docs/guide/how-to-write-a-book.md` («Как написать книгу в LitStudio»), в мокапе встроено сокращённой HTML-версией того же текста. Источник истины — markdown-файл в `docs/guide/`; в приложении он рендерится (не хранится как отдельно поддерживаемая копия текста в коде — расхождение между файлом и тем, что видит пользователь, легко потерять при правках). Руководство — не одноразовый текст: по мере роста функциональности (Фаза 2 и далее) в него добавляются новые разделы, поэтому это `.md`-файл в репозитории, а не захардкоженная строка.

## Экран 2 — «Мобильный»

Отдельный навигационный паттерн, не сжатая версия трёх зон: список сцен ↔ редактор одной сцены, переход по тапу и кнопке «назад».

- **Список** — плоский скроллящийся список глав/сцен (аналог секции «Рукопись» из левой зоны десктопа), без drag-and-drop.
- **Редактор** — на весь экран поверх списка, кнопка «назад» в шапке, тулбар прилипает к низу экрана (не перекрывается системной клавиатурой).
- **Плавающая кнопка «+»** внизу справа — создать сцену.
- **Кодекс, заметки, Корзина, AI-помощники — на мобильном в Фазе 0 не показываются.** Карточка Кодекса открывается только через клик на подсветку упоминания в тексте. Это осознанное урезание объёма функциональности под платформу, не пропуск.

## Выделенные элементы — единый голубой акцент
Любой «выбранный/активный» элемент интерфейса (текущая сцена в дереве, активная роль AI-помощника, и так далее) — светло-голубая заливка с тёмно-синим текстом (`--selected-bg` / `--selected-text` в CSS мокапа), одна и та же пара цветов везде, где есть понятие «это сейчас выбрано». Это отдельная семантика от `.mention` (оранжевая подсветка упоминания сущности в тексте) — не путать местами, у оранжевого другой смысл (ссылка на сущность Кодекса), не «выбрано».

## Явно не показано в мокапе (осознанно, чтобы не тянуть Фазу 2 в Фазу 0)
- Доска сюжета, таймлайн, конспект — их нет в мокапе, потому что их нет в Фазе 0
- Реальная интеграция AI-помощников — правая зона в Фазе 0 визуальная, без подключения к LLM
- Планшетная раскладка отдельно не мокапилась — для планшета логично взять десктопный вариант и на узких значениях переключаться на мобильный паттерн (список↔редактор); точную границу переключения зафиксировать в первом UI-спринте

## Шрифты (не критично, но для единообразия)
Serif для текста рукописи и заголовков — Source Serif 4. Sans для интерфейса — IBM Plex Sans. Mono для счётчиков — IBM Plex Mono. Если каких-то нет под рукой — любой похожий serif/sans/mono, это не блокирующее требование.
